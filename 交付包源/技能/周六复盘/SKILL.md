# 周六复盘

周六复盘有两种触发方式，做的事完全相同：

- **定时触发**：周六窗口到点，由定时入口把本场标为周复盘，核对工具带 `--场次 weekly` 运行。
- **手动触发**：用户在周六（或任何时候）说“周复盘”，按同样的步骤做一遍。

手动触发不限于周六：用户在工作日要求周复盘，做法与周六相同。"本周完成"的统计范围始终按本周（周一至周日）计算。

## 第零步：先确认清单可用

运行核对工具取得完整清单：

```
python 提醒工具.py 清单 --台账 <主表导出> --网格行数 <N> --场次 weekly
```

- 输出第一行是摘要（应覆盖、正常列出、到日待核、搁置、表内异常）。
- 第二行应是"核对：…"，它说明计算日期、核对方式、截止日无法识别的格数。**这一行缺失，说明核对工具没有跑成功**：不要说"本周没有任务"，直接报告"本次未完成核对"，然后停止，等核对恢复。

主表导出怎么取，由台账决定，见交付包的 START-HERE。本 skill 不规定读取方式。

## 第一步：列搁置，逐条问去向

工具列出的"搁置 N 件"段落，**逐条**列出（周六不做工作日那种只报件数的省略）。对每一件只问一句：这件事现在怎么处理——继续搁置、约一个提醒日、还是改成别的状态。没回答的，留在搁置，不要替用户决定。

## 第二步：列可以考虑整理的事，全部列出

工具给出的"可以考虑整理的事"和"最近完成的事"（输出里的原文措辞），**全部列出，不截断，不重排，不增删**。候选顺序和每件的落后天数都照工具给的，不自己算。

对每一件候选，可以给一条降级建议，只能是四种之一：先放一边、转为低优先、和另一件合并、取消。每条建议必须：

- 是候选名单里的事（不能凭空提一件名单外的事）；
- 写明依据（例如"提醒日落后 12 天，且 H 里最近一条记录是 10.20"）。

建议只是建议。**用户逐件决定**，没回答的不动。

## 第三步：整理本周（周报草稿）

周报草稿是给人看的一段回顾，分四块。每一块都要说清楚依据是什么。

1. **本周完成**：只按台账里"结束日期"这一列统计，落在本周内的整件事。这是程序能确认的部分，可以直接列。结束日期为空的已结束事项，单列为"日期未记录"，**不猜日期，不算进本周完成**。取消、归并、转交要分开说明，不混算为"交付完成"。
2. **本周推进**：用户口述或 H 里能确认日期的记录。**不能只靠 H 里的文字推断**：H 的日期是 `M.D` 格式、不带年份，程序不据此判断任何事。H 里只找到很少的本周记录，所以这一块主要依赖用户口述。请用户说，然后原样记下，并注明"据用户口述"。
3. **本周新增**：本周新建的事项。来源同上，依据是用户说的，或者 H 里能确认的首条记录日期。
4. **下周安排**：下周有提醒日或截止日的事项，只列工具给出的日期，不自己换算。

周报草稿保存为文件：

- **位置**：项目目录下的 `周报草稿/` 文件夹，没有就先建。
- **格式**：Markdown（`.md`）。
- **文件名**：`周报草稿_YYYY-MM-DD.md`，日期是复盘当天的日期。
- **同一天再次复盘**：不覆盖已有文件，另存为新版本（例如 `周报草稿_YYYY-MM-DD_2.md`）。已有的版本一个字都不改。
- **周报草稿**：本周完成、推进、新增、下周安排四块，每块写明依据。
- **降级建议**：另存为单独文件，文件名 `降级建议_YYYY-MM-DD.md`，同样在 `周报草稿/` 目录下，同一天另存为新版本。每条建议写明依据；用户没有逐件决定的，标明"未决定"，不替用户改任何一格。

保存后，在对话里告诉用户文件的完整路径。写文件之前，先告诉用户要保存什么、保存到哪，用户没有反对再写。

## 第四步：对用户的回复做处理

用户回复的每一件具体改动，按台账的"对话与写回"规则处理：

- 只改用户说到的那一格，其它不动；
- 写入后回读确认；
- 拿不准的，问一句，不替用户猜。

本 skill **自己不改任何一格**。它只读台账、出清单和建议；改动是用户发出的话之后，由通用指令的写回流程完成。

## 不做的事

- 不自动改 A（状态）、K（提醒日）、N（重点）。
- 不修改规则、指令或任何交付文件。
- 不因为周复盘提前催办已停催、已约未来日期、或已处置的事项。
- 不把"核对"缺失说成"没有任务"。

## 收尾

复盘结束时，用一句话告诉用户：本次一共列了几件搁置、几件候选，用户决定了几件，还有几件没回答。没回答的，留给下一次。
