# 工作全景表

一个人同时管很多事的时候，最怕的不是没能力，是**漏**和**乱**：某件事没人记得去跟，拖到截止日才发现；该催的时候没催，不该催的又一直催；“方案初稿出来了”被当成项目结束；清单一长，重要的和可以放一放的混在一起。

工作全景表用一张在线表格保存每件事的进展，助理每天按固定规则把“今天该推哪一步”讲给你听。你平时不用填表，直接说话就行。

## 适合谁

- 同时负责多条线，事情多、有截止日，也常有“先放一放、过段时间再说”的事。
- 想每天固定时间有人替你过一遍，而不是靠记忆盯事。
- 不想为此维护一套专门的项目管理软件，只想继续用熟悉的在线表格。

它是为一个人的待办与跟进设计的，不适合多人分派任务、需要分权限协作的场景。

## 怎么和它互动

直接说话，不用记编号，不用选菜单。几种常见说法（口语示例，助理按意思理解）：

- “新任务：周五前把报价单发给客户。”——登记。没说怎么提醒，就从明天起每天出现，直到你说做完或放下。
- “方案初稿出来了，还差预算那一段。”——记进展，剩下的动作排在最前，事情仍在办。
- “先放一边，等客户回复再说。”——移入“搁置”：不催，周六再一起看。
- “下周三再提醒我。”——那天之前不催，到了还没处理就继续出现。
- “这件事做完了。”——标记完成，停止提醒，并记下结束日期。
- “不做了，原因是预算砍了。”——标记取消，原因留在记录里，不计入完成。

助理写入表格后会回读一遍确认，并告诉你改了哪几格。你随时可以问“XX 现在什么情况”，这种只查询、不改动。

## 每天会发生什么

| 时间 | 做什么 |
|---|---|
| 工作日 08:30 | **早间清单**：今天要处理的事，重点排在前面。每件一行，行尾直接问“今天推哪一步？” |
| 工作日 17:30 | **晚间复盘**：重新读表，记下今天的进展，再顺带问一两件（最多三件） |
| 周六 10:00 | **周复盘**：列出搁置的事和拖得最久的事，整理本周完成、推进、新增，给出下周安排和降级建议，由你逐件决定 |

清单分三段：

1. **今天要处理的**：到了提醒日、需要你动手的事。
2. **另有在进行的**：还在推进，但提醒日还没到的事，合成一段，只给数量和编号。
3. **需要先补的**：没填提醒日、状态看不懂、需要先确认的事。有才出现。

清单末尾一句说明这次数据核对过、今天的日期。核对没通过，就不发清单，而是直接说明没有完成核对。

## 能达成什么

- **不漏**：到期的事每天出现，直到你说完成、取消或移入搁置。
- **不乱**：重点在前；搁置的事不占每天的清单，但件数对得上，周六能逐条看到。
- **说得清**：每件事为什么这次出现、下次何时再看、为什么退出，都能在记录里查到。
- **只看一遍**：每件事一行，行尾就是要回答的问题，不用在两个序列之间对照。

## 怎么开始用

1. 在你的表格里建一张新表，第一行按交付包 START-HERE 的表头填写。
2. 在本机创建 `运行配置.json`，填入表格标识。仓库里只有结构模板，不含你的表。
3. 在本机创建 `打包_本机禁止词.txt`，每行一个不希望出现在交付包里的词（比如你的表标识和个人路径）。这个文件不进仓库。
4. 运行 `python 打包.py` 生成交付包，再按 START-HERE 完成安装和验证。
